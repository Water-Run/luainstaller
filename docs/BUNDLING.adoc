What `luainstaller` puts in a bundle, and what happens when it starts. You
don't need this to use the tool; it's here for when you want to look
inside.

toc::[]

[#bundling-onedir]
== What's in the folder

[source,text]
----
app/
├── app                          <1>
├── THIRD_PARTY_NOTICES.md
└── .luai/
    ├── manifest.lua             <2>
    ├── generated-output.txt     <3>
    ├── native/                  <4>
    │   ├── liblua-5.4.so
    │   └── lfs.so
    ├── licenses/
    │   ├── Lua-MIT.txt
    │   ├── LGPL-3.0-or-later.txt
    │   └── GPL-3.0-or-later.txt
    └── build/                   <5>
        ├── launcher.c
        ├── generate-onefile-payload.lua
        └── RELINKING.adoc
----
<1> The executable. Your script and all pure-Lua modules are inside it, as
    source text.
<2> What was packaged, with a SHA-256 for every file.
<3> Proof that `luainstaller` made this folder (see <<bundling-ownership>>).
<4> C modules, and the Lua library when it's linked as a shared library.
    On Windows the Lua DLL also sits next to the executable.
<5> The generated C source, so the executable can be rebuilt.

[#bundling-launcher]
== How it starts

. The executable creates a Lua state and opens the standard libraries.
. It sets up `arg` exactly as `lua` would. `arg[0]` is whatever name the
  program was started with.
. It adds the bundled modules and `.luai/native/` to the module search.
. It runs your script, printing a traceback if it fails.

The executable finds its own `.luai/` folder by asking the operating
system, so starting it through a symlink or from `PATH` works.

[#bundling-lua]
== Where modules are looked up

In this order:

. `package.preload`
. modules inside the executable
. the usual Lua file search
. the usual C module search, with `.luai/native/` in front

The bundle comes first, but it isn't sealed: a module that wasn't packaged
can still be found on the host. Test with `LUA_PATH` and `LUA_CPATH`
cleared to catch that.

A C module like `socket.core` is stored both as `.luai/native/core.so` and
`.luai/native/socket/core.so`, so either lookup style finds it.

[#bundling-manifest]
== The manifest

`.luai/manifest.lua` is a plain Lua table. It records the entry script,
Lua version, platform, every module, and a SHA-256 of each file.

Files are identified by a `source_id` relative to the entry script. A file
from outside that folder becomes `external/<sha256>/<name>`.
Build-host absolute paths aren't written into the bundle, so two
people building the same code with the same toolchain get identical
files.

[#bundling-ownership]
== Rebuilding in place

When you build to a folder that already exists, `luainstaller` checks
`.luai/generated-output.txt` first. It starts with
`luainstaller-generated-output-v2` and lists every file and folder in the
bundle, recursive, with its SHA-256.

The old bundle is replaced only if it still matches that exact file set.
If anything was added, removed or edited, the build stops rather than
overwrite your work. Bundles from before this format (v1) need a
one-time removal: delete the folder once, or build to a new path.

Replacement happens in a private staging folder and is swapped in at the
end. If the build fails, the previous bundle is put back.

[#bundling-onefile]
== The single file

A single-file build makes a normal directory bundle first, then wraps it
in a small extractor program (`extractor.c`).

On first run the extractor unpacks the bundle into a per-user folder under
the system temporary directory, then hands over to it. Later runs reuse
that copy if it's byte-for-byte identical.

* On Linux and macOS, the extractor replaces itself with the real program,
  so process ID, signals and exit code behave normally.
* On Windows, the extractor waits for the program. Closing or killing one
  ends the other.

[CAUTION]
====
The payload check exists to avoid unpacking twice. It doesn't protect
against someone modifying the executable. Sign the file yourself if you
need that.
====

[#bundling-licenses]
== Licenses inside the bundle

Every bundle carries the Lua license (`Lua-MIT.txt`), the luainstaller
license (LGPL, plus the GPL text it builds on), `THIRD_PARTY_NOTICES.md`,
and the generated C source in `.luai/build/`. A single file also includes
`extractor.c` and the script that rebuilds its payload.

Keep all of it when you pass the program on. Your own dependencies may
need additional notices. xref:RELINKING.adoc[Relinking] explains what the
files are for.
