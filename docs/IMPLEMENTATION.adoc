[#implementation-flow]
== Request path

[source,text]
----
CLI / Lua API
  -> validate options
  -> discover dependencies
  -> compatibility diagnostics
  -> manifest
  -> directory or single-file bundle
----

Orchestration lives in `src/init.lua`. The CLI only parses and renders.

[#implementation-api]
== API

Exports: `analyze`, `trace`, `compatibility`, `bundle`, `getLogs`,
`clearLogs`.
The structured result contract applies to `analyze`, `trace`, `compatibility`, and `bundle` only.
Success sets `ok = true`. Failure sets `ok = false` and `error`.
`getLogs` returns a list of log records; `clearLogs` returns a boolean.
Unknown options for the structured operations are rejected before
discovery.

[#implementation-supervision]
== Process supervision and budgets

Structured command execution uses a native POSIX supervisor or the Windows
backend. It checks a monotonic deadline and caps captured output; callers
receive an exit code and reason. POSIX commands have a managed process group,
with the direct child PID reserved until cleanup. Windows uses Job Objects
and its legacy watchdog. These mechanisms are not a code sandbox.

`posix_host.lua` builds the standalone helper without Lua headers. Its C source
and `posix_host_source.lua` are synchronized by
`tools/generate-posix-host-source.lua`. The bounded shell bootstrap serves
trusted compiler and filesystem operations before the native helper is ready.
It uses a detected GNU timeout when available, retaining the shell watchdog
fallback otherwise. User-code execution always uses the native supervisor.
A successful cold command kills and collects its watcher directly, avoiding
a race with the watcher's trap installation. Capability probes use the requested
command budget, capped at 30 seconds.
Fixed POSIX process-identity queries use the bounded cold path, so logging
does not compile a host backend while holding its lock.
Static and manual analysis need no POSIX helper.

Options in `init.lua` set byte budgets before parsing. The tracer bounds
snapshots, records and output, and closes its files before reporting failure.
Launcher and onefile C arrays are written in chunks; payload hashing is
incremental. Onefile and trace workspaces unwind unexpected errors as well as
ordinary failures. A byte budget does not replace the worker's OS memory and
disk limits.

POSIX output ancestors must belong to the caller or a system administrator;
untrusted write permissions and links are refused. Protected Android system
ancestors and system root links have explicit handling. Directory identities
are compared before publication. Windows pins non-reparse ancestors for each
file operation and checks volume/file identities before publication. Windows
workspace ACLs and the configured temporary root are deployment trust boundaries.

[#implementation-discovery]
== Discovery

static::
Lex literal require and optional pcall. The entry directory is searched
first. Computed names raise `DynamicRequireError`.

runtime::
Private directory plus tracer. The child interpreter must match the active
runtime identity. Native loader paths and external modules cached before
tracing are rejected; unchanged builtin modules are recognized separately. When the runtime returns loader data naming a readable `.lua`,
that path is recorded. A single complete completion marker is required.

[#implementation-manifest]
== Manifest and ABI

Pure-Lua paths stay relative to the entry. Sources outside the tree use
the stable logical ID `external/<sha256>/<basename>`. The serialized
manifest contains `source_id` values and no build-host absolute paths.
The in-memory build manifest retains physical paths for verification
and diagnostics. Manifest v2 uses SHA-256. A mismatch raises
`SourceChangedError`.

Runtime kind is independent of the Lua C ABI: LuaJIT uses `lua5.1` while
`lua.kind` is `luajit`. Its runtime version, OS, architecture, GC64,
Lua 5.2 compatibility and JIT compiler capability travel with the manifest.
The same identity source verifies discovery interpreters, linked libraries
and generated launchers. These probes run on the native host.

MSVC executables delay-load the Lua DLL and load its adjacent copy by a full
Windows path before creating a state. The generated `lua_min.h` retains the
loader; the compiler driver supplies `/DELAYLOAD` and `/DELAY:NOBIND`.
Native C modules keep ordinary imports.

Explicit `ffi_libraries` join the native file inventory and source snapshots.
The bootstrap binds their logical names to copied paths while the application
runs, then restores `ffi.load`. They do not become `require` modules.

Ownership markers use `luainstaller-generated-output-v2` and recursive
SHA-256 inventories.

[#implementation-onedir]
== Directory transaction

Private `0700` staging, then backup previous output, rename,
revalidate, and quarantine delete. The marker records the final path.
Overwrite decisions use the full v2 tree hashes.

[#implementation-onefile]
== Single-file

Only safe relative paths are accepted. POSIX uses `openat` /
`O_NOFOLLOW` and a UID cache. Windows does not follow reparse points
and holds handles until the child exits. The payload ID is sorted path
plus mode plus size plus content SHA-256.

MoonScript preprocessing invokes the installed `moonc` from a private working
directory, using controlled snapshot filenames. A separate Lua tree preserves
module layout. Private API contexts hold the original hashes and verify them
before both directory and single-file publication. Selected MoonScript inputs
are included in relinking materials. Disabling detection and ordinary Lua
entries bypass compiler lookup and preprocessing.
The entry snapshot keeps its first read. Static discovery prepares excluded
MoonScript modules only when referenced, so their transitive dependencies remain
visible before the final exclusion filter. Exclusions map from original files
to prepared paths without removing a separate Lua file with the same basename.
Windows ASCII case aliases use volume and file identity. Case spelling alone cannot
create a duplicate source, while distinct files still reach the target collision
check. Included aliases map to the same prepared input.
Preparation, source verification and path mapping use protected failure
boundaries. Cleanup also catches thrown filesystem errors and reports a
committed output when publication completed before cleanup failed.
Interruptions keep their structured type, including Lua's plain SIGINT error.
If a lower layer reports a committed output with an error, subsequent diagnostic
or cleanup failures preserve that committed state.

[#implementation-errors]
== Errors

Prefer actionable types: `ScriptNotFoundError`, `LuaSyntaxError`,
`SourceChangedError`, `DynamicRequireError`, `ModuleNotFoundError`,
`DuplicateModuleError`, `InvalidOutputError`, `ToolchainError`,
`CompilationFailedError`, `FilesystemError`, `DiscoveryError`,
`RuntimeTimeoutError`, `ResourceLimitExceededError`,
`UnsupportedPlatformError`, `UnsupportedLuaVersionError`, and related.

Quote every path in shell commands. Reject dangerous compiler-flag
metacharacters.

[#implementation-change-checklist]
== Before changing code

. Add a test that fails on the old behavior.
. Run the four local suites and the syntax checks.
. Review generated C when launcher or extractor changes.
. Run affected multi-version and multi-platform gates.
. Update docs when public behavior changes.
. Confirm that a failed rebuild leaves prior output intact.
. Confirm that a clean environment does not rely on host modules.
