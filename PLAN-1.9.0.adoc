= luainstaller 1.9.0：o1 / o2 / o3 性能优化草案
:toc:
:sectanchors:

o1、o2、o3 从原定 1.8.0 调整至 1.9.0；1.8.0 用于
xref:PLAN-1.8.0.adoc[两套命令重做]。总路线见 xref:PLAN-1.6.1-1.9.0.adoc[开发计划]。

这三档是 luainstaller 自身的优化策略。具体边界、优化集合、默认值和性能门槛，
在基准建立后确定。此稿不承诺未经测量的加速比例，也不把档位直接等同于编译器的 -O 参数。

== 基准先行

扩展 `tools/benchmark-real-world.sh`，保留固定输入、命令、环境元数据和原始样本。
以已验收的 1.8.0 为产品基线，并保留关闭优化的对照模式。

[cols="2,4",options="header"]
|===
|测量层 |指标
|构建 |发现、预处理、生成、编译、发布的分阶段耗时与总耗时
|启动 |冷启动、缓存命中/失效、解包与免解包启动耗时
|执行 |稳态吞吐与延迟；LuaJIT 单独记录预热条件和 JIT 开/关
|资源 |构建与运行峰值内存、产物和材料体积、临时空间及缓存占用
|稳定性 |多次采样的分布、尾部耗时、波动和失败率
|===

样本覆盖小脚本、多模块项目、较大源码、MoonScript、C 模块、FFI、动态发现、
目录和两种单文件模式。包含“没有明显优化空间”的对照项目，避免只选择获益场景。
官方 Lua 五 ABI 与 LuaJIT 分开报告；宿主、架构、编译器、库、参数和缓存状态固定。

区分冷/热缓存和冷/热 JIT，随机或交错安排基线与候选运行。先做预实验，确定采样次数、
波动处理和性能回退预算，再实施候选优化；报告中同时保留中位数、尾部和原始数据。
工具界面的动效与终端输出单独测量，核心性能实验采用可重复的静态/关闭进度设置。

== 候选方向

[cols="1,3,4",options="header"]
|===
|候选档 |倾向 |需要测量和验证的内容
|o1 |低构建成本的通用策略
|减少重复文件工作、复用已验证的探测、生成流程整理；收益与缓存失效条件
|o2 |构建成本和运行收益平衡
|模块布局与加载、构建缓存、工具链优化组合；不同项目与产物模式下的得失
|o3 |显式选择的高成本策略
|LTO/PGO 等能力相关组合、进一步生成方案；构建代价、平台支持和语义证明
|===

上表是候选方向，不是已经确定的档位定义。每项优化说明作用层、适用条件、
失败/不支持时的行为和可独立关闭方式，再依据测量组合成三档。
底层编译器选项按真实能力映射，不能仅根据编译器名称假定支持。

== 正确性与缓存边界

以关闭优化的产物做差异测试：结果、退出码、错误、模块加载顺序、调用副作用、
数值行为和 LuaJIT 开关保持一致。涉及源码或加载变换时，额外验证调试行号、
反射、求值顺序、异常路径和原始材料重链接。

缓存键至少区分工具版本、输入摘要、运行时身份/配置、目标、编译器和构建参数。
源码、库、工具链或策略变化能使缓存失效；并发写入、损坏、权限异常和中断都有回归。
复用结果继续遵守源码快照、输出保护、配额、锁和发布事务，不能跳过这些检查来制造性能收益。

== 接口草案

两种 CLI 和 Lua API 提供关闭优化及 o1/o2/o3 的选择。确切选项名在基准后定稿，
并接入 1.8.0 的命令描述、帮助、文本/JSON 渲染和覆盖清单。
结果记录请求策略、实际策略、适用条件和回退原因；默认值通过数据决定。

动态输入、能力不足、无效策略和优化步骤失败有明确诊断。
有性能回退或额外构建成本时，在指南中说明适用场景，默认行为保持可解释。

== 推进顺序与交付

. 固定基线和样本，发布可重复基准方法与数据格式。
. 按实际瓶颈制作可独立比较的小型候选，完成语义对照。
. 预先设定收益与回退验收线，确定三个档位的集合和默认值。
. 接入 CLI/API、缓存和诊断，跑完整功能、可靠性和性能矩阵。
. 同时报告收益、构建成本、体积/内存变化与退化场景，完成双语指南和正式发布门禁。

进入实现前需要确定：主要瓶颈、每档的稳定收益、默认策略、工具链能力差异以及
性能回退预算。最终仍要求官方 Lua 与 LuaJIT 原生门禁、独立安装、源码身份和公开附件验收。
