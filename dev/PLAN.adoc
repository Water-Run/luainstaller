== 1.9.0：产物运行效率优化

原定 1.8.0 的 o1、o2、o3 移至 1.9.0。三档策略针对生成的可执行产物，
改善其执行吞吐、延迟、启动开销和运行内存；具体边界、优化集合与默认值在基准后确定。
编译与打包耗时仅用于记录采用优化的成本，不作为本版优化目标。

先建立关闭优化的产物基线和真实运行负载，再依据热点选择生成代码、启动、模块加载与
链接策略。详细基准、候选方向、语义约束和接口草案见 xref:PLAN-1.9.0.adoc[1.9.0 草案]。

完成条件：每档有明确行为、产物运行收益、语义回归与可重复的数据；同时说明额外的
编译成本、体积变化和性能回退场景。

== 共同交付条件

* 版本、手册、rockspec、安装脚本和双语文档一致。
* 按 xref:../docs/TESTING.adoc[测试指南] 完成本地检查；发布提交通过官方 Lua 和 LuaJIT 原生门禁。
* 验证独立安装、升级、两种 CLI、API 和移除源码后的产物运行。
* 标签与发布附件来自同一提交；发布后下载并核对全部附件。
* 发布步骤以 xref:../docs/TESTING.adoc#testing-luarocks[发布] 为准，中文副本保持一致。
  包括五个 GitHub 附件的 `sha256sum -c SHA256SUMS`、`luarocks upload ROCKSPEC SRC.ROCK`、
  上传报告 `unexpected eof while reading` 时改走文档中的 curl 命令、
  LuaRocks 字节与 GitHub 文件一致，以及空树和旧版升级两次无版本号安装。
  索引里缺的更早 GitHub rock 一并上传。API key 留在本机配置里。
* Release 只写用户可见的变更和必要说明；审计、测试与发布证据另行保存。
