=== 默认系统安装的补充验收

2026-10-12 用户再次报告 `sudo luarocks install luainstaller` 仍停留在 1.4.0。
本机复核发现，普通用户优先访问官方源，而 root 的
`/root/.luarocks/config-5.4.lua` 只配置了 Moonrocks GitHub 镜像。
官方页面和 5.4 索引已包含 1.5.0、1.5.1，镜像索引只到 1.4.0，两个新包返回 404。
这属于安装渠道选择与传播问题，不能以官方上传成功关闭用户的安装问题。

已将 root 配置备份到任务私有证据目录，设置官方源优先、保留镜像作为备选。
执行普通、不指定版本的 `sudo luarocks install luainstaller` 后，系统 `/usr/local`
安装升级为 1.5.1，旧 1.4.0 已删除；`luai -v` 和 `luainstaller version` 均为 1.5.1。
此后每个节点除空安装树外，也核验实际用户与 sudo 的源选择及已有安装升级。

后续用户复现了另一条失败路径：官方索引下载出现 `unexpected eof while reading`，
LuaRocks 回退到旧镜像，并把已经安装的 1.5.1 降级到 1.4.0。
之前保留过期镜像作为备选的处理不充分。现已从 root 配置移除该镜像，
只保留官方源；本机 LuaRocks 3.13.0 改用系统 wget/curl 下载，开启证书校验，
再次将系统安装恢复到 1.5.1。连续三次普通无版本安装均选择 1.5.1，两个 CLI 均验证为 1.5.1。
使用空缓存和下载失败替身模拟源不可用时，安装返回失败、未访问旧镜像、已有 1.5.1 保留。
验收期间一度出现安装锁冲突，原因是两个测试同时写同一系统安装树；随后改为串行验收，
没有使用强制解锁，最终没有遗留锁。此后涉及同一安装树的安装、卸载和故障注入均串行执行。
发布包不改写使用者的 LuaRocks 配置；镜像滞后时在故障排查指南提供官方源安装命令。

== 阶段 2：v1.6.0 单文件模式

保留目录模式。单文件构建增加一个选择项，计划 CLI 为
`--file-mode auto|extract|no-extract`，API 为 `onefile_mode`。
既有 `--file` / `--onefile` 进入单文件模式，默认选择 `auto`。

[cols="1,3,3",options="header"]
|===
|模式 |行为 |无法满足时
|`auto`
|纯 Lua 且具备经过验证的静态 Lua 链接能力时选择免解包；其他情况选择解包。
|报告实际选择及原因。普通编译失败不能伪装成“能力不足”后悄悄换一种产物。
|`extract`
|显式使用现有自解包形式，保留 C 模块和动态 Lua 运行库支持。
|返回具体构建错误。
|`no-extract`
|生成直接启动的单个程序，Lua 代码内嵌，Lua 运行库静态链接。
|存在必须外置的 C 模块、缺失静态 Lua 或 ABI 不匹配时明确失败，不降级为解包。
|===

免解包的验收对象是最终产物。启动不创建或写入解包目录，不启动一个内层程序，
不要求目标机安装 Lua 或 MoonScript。正常系统库仍按平台约定使用。

[%interactive]
* [ ] 从当前内嵌源码启动器提取免解包构建路径，避免先生成再解包一个 onedir。
* [ ] 为纯 Lua 验证 Linux、macOS、Windows 的静态 Lua 能力；Windows 区分静态库与 DLL 导入库。
* [ ] 构建结果记录请求模式、实际模式、选择原因，CLI 在需要时清楚呈现。
* [ ] 保持参数、退出码、信号、可重现构建及构建路径隐私。
* [ ] 保留许可证和可重链接材料的获取方式，并验证重链接后的程序。
      材料的按需导出不属于程序正常启动过程。
* [ ] 验证无可写临时目录、无已安装 Lua、源文件移除后的运行行为。
* [ ] 验证自动选择、显式选择、能力不足、含 C 模块和失败回滚。

截图中的“内嵌字节码”和“运行时免解包”分别评估。当前内嵌源码已经可以直接加载，
免解包不以接受外部字节码为前提。若增加字节码格式，只能使用受控编译器生成的

== 阶段 3：v1.6.0 MoonScript 输入

用户请求的入口行为：

[cols="2,3",options="header"]
|输入与设置 |行为
|`.moon`，默认设置，本机有编译器
|调用本机 `moonc`，把 Lua 输出写入私有临时目录，随后执行原有分析/打包流程。
|`.moon`，默认设置，本机没有编译器
|返回明确诊断，提示安装 MoonScript 后重试同一命令即可；不自动安装依赖。
|`.moon`，显式禁用
|直接按既有 Lua 输入处理，不执行 MoonScript 检测或编译。
|`.lua`
|保持既有流程，不探测或启动 MoonScript 编译器。
|===

禁用开关为 `luainstaller --no-moon-detect`，`luai` 使用短选项 `-M`，
API 为 `moon_detect = false`。禁用时不探测 PATH、不启动命令、不扫描 MoonScript
文件；用户给出的内容直接交给原有 Lua 流程。
实现只调用设备上的编译命令，不在当前 Lua 进程中 `require("moonscript")`，
也不通过 `moon` 执行待打包项目来完成默认编译。

[%interactive]
* [ ] 检测命令实际能力；不能仅依赖无文件参数的 `moonc --version` 退出码。
* [ ] 对单文件与多模块 MoonScript 项目生成保持目录关系的 Lua 暂存树。
* [ ] 支持与 Lua 模块混用；`.moon` 和 `.lua` 编译目标冲突时明确拒绝覆盖。
* [ ] 在整个流程结束后清理暂存目录，覆盖编译失败、后续失败、超时和中断。
* [ ] 编译和分析不改写原项目；记录原始源标识，校验构建期间源文件变更。
* [ ] 支持现有 static/manual/runtime 发现模式及 include/exclude 语义；
      诊断能把暂存 Lua 与原始 MoonScript 文件对应起来。
* [ ] 对编译器缺失、损坏、错误输出、非零退出及危险文件名建立回归测试。
* [ ] 验证禁用开关绕过全部 MoonScript 检测工作；用会失败的探测替身证明没有调用，
      不仅凭执行时间判断是否跳过。
* [ ] 在真实安装的 MoonScript 上验证端到端流程；mock 命令只用于异常分支测试。
* [ ] 验证生成产物不需要 MoonScript 环境，并与三种单文件模式组合测试。

官方接口依据：https://moonscript.org/reference/command_line.html[MoonScript 命令行文档]。
本机已有 `moon` 和 `moonc` 0.6.0，可用于实际编译验证。
