This file records user-visible changes. The release tag remains the source of
truth for the exact contents of a published version.

== Unreleased

== 1.4.0 - 2026-09-22

=== Added

* Offline, LuaRocks-free installation with `lua tools/install.lua --prefix
  <new-directory>` on POSIX and native Windows. Dedicated installations are
  relocatable and include both command wrappers, the Lua API, docs and notices.
* Source entry points `bin/luai.lua`, `bin/luainstaller.lua` and the root
  `luainstaller.lua` library loader, plus installation and next-release guides.
* Standalone installation coverage for relocation, API use, directory/single
  file builds, clean-target execution and refusal to overwrite an existing tree.

== 1.3.0 - 2026-08-24

=== Added

* Capability-driven native profiles for 32-bit x86/ARM, Android/Termux,
  FreeBSD and other ELF/POSIX hosts. Host detection now distinguishes a
  32-bit userland from a 64-bit kernel and records Android as its own target.
* Verified static-liblua fallback on POSIX. Linux, Android and the BSDs can
  build from either a shared library or `liblua.a`; a statically linked
  launcher exports the Lua C API so ordinary native modules continue to load.
* Windows linker-machine selection for x86, x86_64, ARM and ARM64, including
  MinGW `.dll.a` import libraries and an XP (`_WIN32_WINNT=0x0501`) API
  baseline for x86/x86_64 generated launchers and onefile extractors. PE
  subsystem floors are 5.01 on x86 and 5.02 on x86_64.

=== Changed

* Replace Linux-specific `libdl`, `/bin/sh`, `ldd`, `/proc/self/exe`, GNU
  `find -mindepth`, and GNU `timeout` assumptions with OS capabilities or
  safe fallbacks. FreeBSD launchers use `KERN_PROC_PATHNAME`; generic POSIX
  launchers resolve `argv[0]` through `PATH`; Termux uses its app-private
  prefix for temporary extraction when needed.
* Lower generated compiler requirements from mandatory C11 to portable C99.
  Windows process/filesystem bridges avoid post-.NET-2 APIs so PowerShell 2
  remains usable on Windows XP; `/Brepro` is used only when the linker reports
  that capability. Windows onefile publication uses the same-volume,
  no-replace `File.Move` path instead of an administrator-only hard-link tool.
* Runtime-library probing no longer requires `ldd` when an exact accepted
  shared-library candidate has already passed the native compile-and-run ABI
  probe. ELF SONAME (or the macOS install name) inspection preserves the
  loader-visible runtime filename when the candidate itself has another name;
  macOS dylib output must remain relocatable through `@rpath`.
* Release-source hashing accepts FreeBSD's native `sha256` command in addition
  to GNU `sha256sum` and macOS `shasum`.

=== Fixed

* Restore byte-identical MSVC onefile builds by applying `/Brepro` to both the
  compiler and linker after a real option probe; some supported linker builds
  omit this option from `link.exe /?` help text.
* Keep onefile descendant containment on Windows XP without assuming the
  newer `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` flag. When that flag is rejected,
  an inherited-handle watchdog terminates the same Job Object after an abrupt
  outer-process exit; normal completion also terminates the job explicitly.
* Treat an inherited `TMPDIR=/tmp` as unavailable on Termux and consistently
  fall back to the application-private prefix for both builds and extraction.

== 1.1.1 - 2026-08-22

=== Changed

* Make the GitHub Actions Linux and Windows/MSVC five-version matrices the
  required release gate. Supplemental lab runs remain useful evidence without
  making a physical Windows 11 device or any other specific host a release
  prerequisite.

=== Fixed

* Preserve build-wide `SIGINT`/`SIGTERM` delivery when compiler commands are
  supervised by GNU `timeout`; timed commands run in a managed process group
  so runaway descendants cannot survive or hold the captured-output pipe open.
* Track `require` bindings correctly across sibling `else`/`elseif` branches,
  numeric and generic `for` variables, qualified and local function names,
  multiline and multi-name declaration initializers, `repeat` conditions,
  table-constructor field names, and global rebindings that cross lexical
  blocks. Direct assignments now inspect their right-hand side before the new
  `require` binding takes effect.
* Make streamed file hashing report read and close failures instead of
  accepting a partial digest, and encode SHA-256 lengths correctly beyond
  4 GiB.
* Use streamed SHA-256 for manifest snapshots, copied-file verification, and
  final source revalidation; repeated native aliases no longer rehash the same
  source.
* Keep Windows build transactions below the legacy `MAX_PATH` boundary by
  using compact, collision-resistant sibling names while retaining the full
  ownership token in the lock record. Preserve the established POSIX sibling
  names.
* Keep compiler object and import-library intermediates out of published
  onedir/onefile payloads. MSVC executables remain reproducible across checkout
  roots even though its `.obj` files encode build-local details.
* Read Windows environment paths through the Unicode-safe PowerShell bridge,
  so logging continues to work when the user or temporary directory contains
  non-ASCII characters.
* Complete PATH-based MSVC discovery with companion `lib.exe` and
  `dumpbin.exe`, and tolerate the Windows SDK 10.0.19041 `C5105` header warning
  while retaining `/W4 /WX` for all other diagnostics.
* Align the LuaRocks dependency with the implementation contract: official Lua
  `>= 5.1` and `< 5.6`.
* Repair the GitHub Actions gates: use a pinned shared Lua 5.4.8 and pinned
  sample inputs, install the complete offline dependency graph needed by every
  bundled example, export paths through the environment files so `$HOME` and
  `$PATH` are expanded by the shell, update the checkout action, and make
  downloads retry without publishing or retaining partial files. Run the five
  official Lua ABIs as independent jobs so their comprehensive suites do not
  share one 120-minute timeout.
* Refresh both release matrices and the bundled Lua notice to the current
  official Lua 5.5.1 patch release and its published SHA-256 digest.
* Fetch release-matrix inputs from SHA-256-verified mirrors, pinning rock and
  lsqlite3 inputs to immutable commits. Pin the compiled lsqlite3 0.9.6 C
  source itself instead of a Fossil-generated ZIP whose container bytes can
  change independently of the source.
* Repair the manual real-world benchmark: replace the removed TinyKeep source
  with Luacheck's parser graph, use valid LuaSocket APIs, pass native module
  paths to the offline fallback, isolate clone and dependency-install logs,
  and return failure when a required analyze, bundle, or runtime probe fails.
* Make the Windows release runner work under PowerShell 5.1 by capturing the
  version banner from stderr, and make lifecycle coverage distinguish the one
  required inner process from the optional console host process.
* Make direct MSVC builds use the compatibility defines from each official Lua
  source Makefile. In particular, Lua 5.3 now registers the expected `bit32`
  library, and cache identities invalidate binaries built without those flags.
* Make Windows Unicode process coverage independent of the machine's active
  ANSI code page while retaining native Unicode argv, environment, and
  filesystem checks.
* Terminate generated `payload.inc` files with a newline so current Clang
  accepts both original and relinked onefile sources under strict warnings.
* Correct reproducibility and distribution-license fixtures so every declared
  nested checkout and output component is actually part of the tested path.
* Stop Windows path adapters from leaking `string.gsub`'s replacement count.
  Extracted onefile payload regeneration now works with Lua 5.2+, and
  successful private-directory creation again returns only the path.

== 1.1.0 - 2026-08-14

=== Added

* Incremental SHA-256 (`newSha256`, `updateSha256`, `finalizeSha256`) and
  64 KiB streamed file hashing, with a native-operator backend on Lua 5.3+.
* A real-world benchmark matrix covering pure Lua projects, runtime discovery,
  native modules, Neovim-scale trees, and synthetic 100/1,000/10,000-module
  projects.
* A GitHub Actions smoke workflow alongside native release-matrix tooling.
* Equivalence contracts for the source and generated runtime implementations,
  plus compiled equivalence checks for the two launcher templates.

=== Changed

* The supported interpreter contract is explicit: official Lua 5.1 through
  5.5; LuaJIT and other non-official runtimes are rejected.
* `clang-cl` uses the MSVC argument family. Compiler commands default to a
  900-second bound and toolchain probes to 120 seconds on Windows and on POSIX
  hosts with GNU `timeout`; `LUAI_CMD_TIMEOUT` overrides both values.
* Static discovery understands common local, parameter, and function-body
  `require` shadowing forms and continues discovery after goto labels.
* Native alias destinations such as `socket/core.so` are recorded in the
  distribution manifest.
* Helper return contracts were tightened, invalid logger fields now fail
  loudly, and undocumented `-limit`/`-level` CLI aliases were removed.

=== Fixed

* POSIX file copies no longer overwrite an existing destination, matching the
  Windows behavior.
* Manifest hashing applies the regular-file/no-symbolic-link policy when the
  process-backed filesystem inspection path is available, while retaining the
  minimal no-`io.popen` compatibility path.
* CLI options no longer silently consume another known option token as their
  value.
* PID-less legacy logger locks use a longer stale-age floor before recovery.
* Onefile extraction validates Windows reserved names and invalid path
  characters, persists the payload directory, and cleans files created by a
  failed extraction.
* Remote archive checks, real-world benchmark discovery options, and all
  release-tool references were updated for the 1.1.0 rockspec.

=== Upgrade notes

* Re-run static analysis for projects that intentionally shadow `require`; use
  runtime discovery or explicit includes for computed module names and
  indirect `require` aliases. The exact `local require = require` passthrough
  remains recognized.
* Lua 5.5 requires LuaRocks 3.13.0 or newer.
* Rebuild artifacts on each target OS/architecture/Lua ABI; outputs are not
  cross-platform binaries.
