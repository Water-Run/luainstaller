= luainstaller 1.8.0：完整命令重做计划
:toc:
:sectanchors:

本文件规划 1.8.0，基线为 1.7.1。它描述待实现能力，不表示这些能力已经发布。
xref:PLAN-1.7.2.adoc[1.7.2] 先补齐 LuaRocks 安装材料，不改变本计划的命令范围。
总路线见 xref:PLAN.adoc[开发计划]；面向产物运行效率的 o1/o2/o3 优化器安排在
xref:PLAN-1.9.0.adoc[1.9.0 草案]。

== 交付目标

`luai` 延续 Lua 工具的简洁风格：短入口、纯文本、少量必要信息、直接的错误。
`luainstaller` 面向现代终端：完整的帮助、分组结果、清晰诊断、语义高亮、色彩和真实进度动效。
两种入口执行相同的核心操作，产生相同的产物和退出状态。

覆盖范围包括两个命令名、源码入口、LuaRocks 安装入口、独立安装的 POSIX/Windows 包装器，
以及 `cli.main(args, context)`。逐项覆盖命令、别名、子参数、flag、正常与异常输出，
同时处理 TTY、重定向、管道、CI 和能力不足的终端。

CLI 风格只影响工具界面；生成程序保留应用自己的输出与行为。
安装、重链接和生成程序的材料导出入口纳入交付回归，保持已有调用方式。

== 两套风格的契约

[cols="2,3,4",options="header"]
|===
|项目 |luai |luainstaller
|命令入口 |`-h -v -a -t -b -l` |`help version analyze trace build logs`
|默认输出 |简短、稳定的文本行；必要的计数、路径和错误 |完整摘要、分组详情、清晰层级与下一步提示
|帮助 |紧凑的命令与选项清单，短名称优先 |总帮助、命令帮助、分组选项、默认值、范围、别名、示例与关联用法
|色彩 |纯文本 |按终端能力自动选择，允许显式开关
|动效 |静态输出 |阶段指示、等待动画、真实进度条、耗时与计数更新、完成状态切换
|详细模式 |保留 `--verbose` 的实用补充信息 |展开决策、候选路径、工具链命令和完整诊断
|管道 / CI |保持原有简洁文本 |完整静态文本；显式 JSON 模式供程序读取
|警告 / 错误 |短错误类型、原因和必要路径 |问题、发生阶段、相关选项/路径、可执行建议与恢复状态
|===

`luai` 的既有字段名、行格式和退出码先建立快照，变化逐条评审。
现代入口可以重新排版，但核心结果、错误类型、输出保护和取消语义保持一致。
必要的警告、已提交产物状态和清理失败信息在两套风格中都可见。

== 现有子参数和 flag 的完整盘点

下表是实现与验收清单。已有长短别名在两个入口中继续可用；帮助按照各自风格排列。
共享解析器当前接受但操作不使用的选项，需要逐项写入兼容迁移表，明确提示或拒绝，
不能继续静默忽略，也不能未经记录改变既有调用。

[cols="3,2,4",options="header"]
|===
|参数 / 别名 |值或形式 |重做与验收重点
|`ENTRY` |`.lua` / `.moon` 路径
|缺失、多余位置参数、空格、引号、Unicode、相对/绝对路径；以 `-` 开头的文件提示使用 `./`
|`--dir` / `--onedir` |布尔，build / trace
|目录模式和默认值；与单文件选择冲突时明确报错
|`--file` / `--onefile` |布尔，build / trace
|自动选择单文件模式；摘要展示实际选择与原因
|`--file-mode` |`auto` / `extract` / `no-extract`
|每个值、缺值、未知值、目录冲突、静态库不可用、原生/FFI 限制
|`-M` / `--no-moon-detect` |布尔
|禁用 MoonScript 检测后的实际行为、帮助和错误
|`-o` / `--out` |路径
|默认输出、显式输出、非法目标、已有目录、输出保护和发布后的最终路径
|`--include` |可重复路径
|逐项验证、重复项、显式依赖、MoonScript 映射与总量限制
|`--exclude` |可重复名称或路径
|名称/路径/后缀语义、被排除项、与显式输入的关系和 trace 展示
|`--ffi-library` |可重复 `NAME=PATH`
|名称、重复名称、路径、运行时要求、依赖总数和产物模式；清楚区分 FFI 库与 C 模块
|`--target-os` |宿主 OS 断言
|使用当前宿主标识，如 `linux`、`windows`、`macos`、`freebsd`、`android`；
未知值、大小写错误、跨目标请求和当前宿主信息，继续要求与实际宿主匹配
|`--lua` |解释器路径
|运行时发现使用的解释器；匹配运行时种类、版本和构建配置
|`--lua-prefix` |匹配的运行库前缀
|自动/显式发现、错误前缀、选中库和能力不足的诊断
|`-d` / `--discovery-mode` |`static` / `manual` / `runtime`
|三种模式、默认值、无效值、动态 require、LuaJIT 语法回退与执行路径边界
|`--no-depscan` |布尔
|手动发现别名；与显式 discovery-mode 的组合规则
|`--max-deps` |正整数
|默认 36、有效范围、合并依赖与 FFI 名称限制、重复项和临界值
|`--runtime-timeout` |有限正秒数
|小数秒、上下界、缺值、无穷/NaN、真实超时和取消后的清理
|`--max-source-bytes` |正整数字节数
|单源限制、单位、上下界与源文件路径
|`--max-bundle-bytes` |正整数字节数
|合计输入/产物限制、FFI/原生文件、超限阶段和输出保护
|`--max-trace-bytes` |正整数字节数
|运行时 trace 上限、缺值/错误值和真实超限
|`--verbose` |布尔
|所有支持它的命令有明确附加字段；正常、警告和失败都覆盖
|`--` |后续参数原样透传
|用于运行时发现的入口参数；保留顺序、空字符串、引号和类似选项的值
|`--level` |`debug` / `info` / `warning` / `error` / `success`
|logs 的每个级别、无匹配记录、缺值和无效值
|`--limit` |正整数
|logs 的默认、上限请求、实际返回数量、缺值和无效数值
|`--asc` |布尔
|logs 正序；默认倒序；相同时间戳保持对应写入顺序
|===

所有带值的长选项规划同时支持 `--name value` 与 `--name=value`。
布尔选项不接受意外的 `=value`；同值重复可归一化，非列表选项的冲突值、冲突的模式
和多余参数统一拒绝。include/exclude 保留列表累积；FFI 名称重复沿用明确报错。
`--` 保留参数透传含义，帮助中明确它与入口路径的关系。
`help` 和 `version` 也校验多余参数，避免把拼错的选项当作成功请求。

作用域定稿如下：输入/发现/预算选项适用于 analyze、trace、build；
`--dir` / `--file` 在 trace 中保留兼容性预览作用，`--file-mode` 与输出路径属于 build。
runtime 专用选项在其他发现模式中列为未启用：现代配置摘要和 classic verbose 明确显示，
帮助说明触发条件。与操作完全无关的选项在迁移表中标注为参数错误。
日志筛选选项只作用于 logs；verbose 规划扩展到 logs 的 details 和 version 的安装信息。

数值帮助直接给出单位、默认值与范围：依赖默认 36、最大 2147483583；单源默认 8 MiB、
合计默认 128 MiB、trace 默认 32 MiB，字节预算最大 1 GiB；runtime 默认 30 秒、最大
86400 秒。实现时从核心契约核对这些值。logs 默认返回全部保留的匹配记录，limit 指返回上限。

== 新增展示控制

这些选项属于现代 `luainstaller` 入口。`luai` 的简洁纯文本输出不依赖它们。

[cols="2,3,4",options="header"]
|===
|选项 |值 / 别名 |行为
|`--color` |`auto` / `always` / `never`；`--no-color` 等同 `never`
|默认自动；显式 always/never 优先于环境自动判断
|`--progress` |`auto` / `plain` / `off`；`--no-progress` 等同 `off`
|auto 在合适 TTY 中显示动效；plain 输出静态阶段行；off 保留最终结果和必要诊断
|`--format` |`text` / `json`
|默认 text；json 输出完整、可解析的结构化结果，关闭色彩与进度重绘
|===

展示选项可位于现代命令前后，命令帮助列出其适用范围。
JSON 模式优先于色彩与进度配置。每个请求在 stdout 产生一个结果对象，失败仍返回
对应非零退出码；进度、横幅、提示或子进程文本不会混入 JSON 对象之外。
子进程诊断进入结构化字段，渲染器不改变核心错误类型。
help/version 的 JSON 也有定义，命令解析失败能输出可解析的错误对象。

JSON 明确 `schema_version`、`command`、`ok`、`result`、`warnings`、`error` 等字段，
给出成功、空结果、失败示例及字段兼容规则。stdout 的机器格式与人类文案分别测试。

== 输出流、终端能力与降级

分别检测 stdout 与 stderr：结果走 stdout，进度和诊断走 stderr。
stdout 被重定向但 stderr 仍连接终端时，进度可以保留，结果文件保持干净。

色彩自动策略按真实输出流的 TTY 能力、`NO_COLOR`、`CI`、`TERM=dumb` 和
Windows 控制台 VT 能力判断。显式 `--color` 的 always/never 优先；JSON 始终无 ANSI。
自动模式在管道、CI 和不支持重绘的终端中输出静态文本。

支持常用 ANSI 色阶和 True Color 的能力分级，准备 ASCII 图标与纯文本后备。
信息含义也由文字/符号表达；不依赖颜色或特殊字体辨认成功、警告与失败。
`--progress=plain` 提供无动画但保留阶段信息的选择。

按终端宽度布局，覆盖窄终端、窗口变化、长路径、CJK、组合字符、多行消息和无宽度信息。
长字段换行或转为逐字段布局，保证结果完整可复制；控制字符显示为可见转义。
不要求额外终端主题、字体、常驻进程或 PowerShell 才能使用普通命令。

== 动效与进度设计

[cols="2,3,3",options="header"]
|===
|动效 |使用场景 |数据与结束条件
|等待指示器 |探测、编译等总量未知阶段 |真实阶段事件与计时；不显示虚构百分比
|进度条 |已知总量的文件/字节处理 |真实 done/total，包含计数和单位
|阶段列表 |发现、预处理、生成、编译、验证、发布 |pending/running/success/warning/error 状态，完成后保留静态摘要
|实时统计 |长任务耗时、已处理模块/文件 |限频刷新；终止后保留最终值
|完成切换 |成功、失败或取消 |清理活动行，切换为有文字说明的最终状态
|诊断插入 |过程中的警告或 verbose 子进程输出 |先清除进度区，写入完整内容，再安全恢复进度
|===

刷新采用单调时钟并限频，目标不超过每秒 12 次，不增加人为等待来展示动画。
不默认切换全屏或清除用户滚动历史。成功、错误、SIGINT、中途异常和关闭管道后
都恢复光标及终端属性，避免留下残缺控制序列或把错误覆盖掉。

当前同步调用只在操作前后打印字符，无法表现长时间编译中的真实动效。
需要为 Lua 长循环和受监督子进程等待提供进度更新点；原生等待过程可产生定时 tick，
同时继续执行超时、输出预算、中断与子孙进程管理。

== 内部结构与兼容性

. 建立命令描述表：命令/别名、位置参数、flag、值类型、默认值、范围、适用操作、
  冲突关系和帮助文本。检查清单与帮助、解析器、文档相互核对。
. 把解析后的标准选项交给现有 API；把成功、警告和错误转为统一的展示数据。
. 分离 classic 与 modern 渲染器，使用同一份操作事实；核心模块不生成 ANSI 或终端文案。
. 增加终端能力层、静态文本/JSON 输出和进度控制器，避免把渲染条件散落在业务代码中。
. 事件携带阶段、状态、计数、耗时及诊断；渲染回调失败时停止动效并保留核心结果，
  不把已完成的构建误报为未提交。
. 同步源码加载器、独立安装复制规则、rockspec 与安装入口；新增模块随两种安装方式交付。

命令描述不是行为测试的唯一依据：保留独立的输入/输出与退出码预期，防止解析器和帮助
同时遗漏某个选项却互相验证通过。1.7.1 的正确性、预算、日志顺序和材料完整性回归继续保留。

动画测试使用可控时钟与真实事件，验证顺序、清理和刷新预算，不要求某一时刻恰好显示某帧。
宽度/能力模拟仅证明逻辑分支，平台支持声明仍以原生执行为准。
