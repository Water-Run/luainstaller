= luainstaller 1.9.0：产物运行效率优化草案
:toc:
:sectanchors:

o1、o2、o3 从原定 1.8.0 调整至 1.9.0；1.8.0 用于
xref:PLAN-1.8.0.adoc[两套命令重做]。总路线见 xref:PLAN.adoc[开发计划]。

三档是 luainstaller 为生成产物提供的运行效率优化策略，目标是让打包后的应用运行得更好。
具体优化集合、档位边界、默认值和性能门槛在基准后确定。
编译与打包速度不属于优化目标；构建耗时和构建内存只用于衡量优化成本。

== 先测量产物运行

以已验收的 1.8.0 为基线，生成关闭优化的对照产物。
扩展 `tools/benchmark-real-world.sh` 的实际运行负载与数据采集，不能只比较分析或打包耗时。
固定输入、工作量、宿主环境和运行时，保存命令、环境元数据与原始样本。

[cols="2,4",options="header"]
|===
|类别 |指标与用途
|执行效率
|真实工作负载的吞吐、总执行时间、响应延迟和尾部延迟；作为主要收益指标
|启动开销
|进程启动到应用就绪、首次模块加载和单文件解包的耗时；与稳态执行分开报告
|运行资源
|产物运行期间的峰值/稳态内存、CPU 消耗和临时空间；核对速度提升的代价
|稳定性
|重复运行的分布、波动和失败率，覆盖持续运行与短命令两种场景
|采用成本
|编译耗时、构建峰值内存、产物体积；用作成本约束，不计为运行加速收益
|===

样本覆盖短脚本、计算密集型程序、多模块应用、MoonScript、C 模块、FFI 和动态加载，
同时覆盖目录、解包单文件和免解包单文件。每个样本固定实际工作量并核对计算结果，
包含没有明显优化空间的对照，避免只选择获益场景。

官方 Lua 五 ABI 与 LuaJIT 分开报告。LuaJIT 分别测量 JIT 开/关、预热前后；
区分首次启动与重复启动、冷/热文件缓存。对照与候选交错运行，控制后台负载。
先做预实验确定采样次数、波动处理和回退预算，再评估各档；保留中位数、尾部与原始数据。

打包器的终端动效不参与运行收益统计。产物仍执行相同的应用逻辑，不能通过删减工作量
或改变输出制造性能提升。

== 候选策略

[cols="1,3,4",options="header"]
|===
|候选档 |倾向 |待验证的产物运行优化
|o1
|成本较低、适用面较广
|优化生成程序的初始化与模块查找，减少运行时重复工作；选择有实测收益的生成 C 配置
|o2
|更积极的运行优化
|依据应用热点优化模块加载、数据布局和生成代码，组合有效的编译/链接选项，比较吞吐与内存变化
|o3
|显式选择、允许较高构建成本
|评估 LTO、PGO 等策略对实际产物的收益；使用代表性的运行样本训练，并在独立负载上验收
|===

上表是候选方向，不是最终档位定义。每项策略记录作用位置、运行收益、适用条件、
额外成本与关闭方式，再据数据组合成三档。o1/o2/o3 不直接等同于编译器的 -O 参数。
构建缓存、文件复制提速、探测缓存和打包流程提速不列入本轮候选。

Lua 代码仍由所选 Lua 或 LuaJIT 执行；只优化启动器的 C 编译参数，不能推导出应用热循环
也会加速。需要先定位产物运行中的真实热点，再选择能作用于该热点的方案。
预编译的 Lua 运行库、C 模块与 FFI 库也不会因启动器选项改变而自动得到优化。

LTO/PGO 按编译器、运行库和链接方式实际探测；不具备条件时给出明确诊断。
不预设改写用户 Lua 源码。若数据支持引入源码变换，先单独论证语义与可调试性，
再决定是否纳入某一档。

== 正确性约束

与关闭优化的产物做差异验证：计算结果、输出、退出码、错误、模块加载顺序、调用副作用、
数值行为和 LuaJIT 开关保持一致。启动与模块查找优化继续遵守 `require` 的既有语义。

涉及加载或源码变换时，额外验证调试行号、反射、求值顺序和异常路径。
保留原始材料与可重链接能力；输出保护、配额、锁和发布事务的现有回归继续执行。
如果策略保存 PGO 数据等产物相关材料，记录输入、运行时、编译器和策略身份，
在不匹配时拒绝复用。

== 接口草案

两种 CLI 和 Lua API 提供关闭优化及 o1/o2/o3 的选择。确切选项名在基准后定稿，
接入 1.8.0 的命令描述、帮助、文本/JSON 渲染和覆盖清单。
结果记录请求策略、实际策略和回退原因；默认策略由运行收益与兼容性数据决定。

动态输入、能力不足、无效档位和优化失败都给出明确诊断。
指南说明各档适用的运行负载，以及额外编译成本、内存/体积变化和已知回退场景。

== 推进顺序与交付

. 固定关闭优化的产物与运行负载，公开可重复的测量方法和数据格式。
. 按产物运行热点制作可独立比较的候选，先完成语义对照。
. 预先设定运行收益、回退和成本验收线，确定三档集合与默认值。
. 接入 CLI/API 和诊断，执行功能、可靠性及产物运行性能矩阵。
. 报告吞吐、延迟、启动与运行内存的变化，以及额外构建成本和退化场景；完成双语指南和发布验收。

进入实现前需要确定：主要运行瓶颈、每档稳定收益、默认策略、平台能力差异和回退预算。
最终仍要求官方 Lua 与 LuaJIT 原生门禁、独立安装、源码身份和公开附件验收。
