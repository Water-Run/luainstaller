== V72-01：LuaRocks 安装丢掉 LICENSES

优先级：P2。安装报告成功，许可证目录不在安装树里。
生成产物的许可证字节不受影响。

触发：在本机用 LuaRocks 3.13.0 和 GNU cp 执行

[source,bash]
----
luarocks make --tree "$TREE" luainstaller-1.7.1-1.rockspec
----

错误结果：命令退出码为 0，并打印
`cp: 未指定 -r；略过目录 'LICENSES'`，随后写
`luainstaller 1.7.1-1 is now installed`。
安装树 `lib/luarocks/rocks-5.4/luainstaller/1.7.1-1/` 没有 `LICENSES/`。
`doc/` 里有 `LICENSE`、两份 README、`THIRD_PARTY_NOTICES.md` 和 `AGENTS.md`，
没有 `docs/`、`CHANGELOG.adoc` 或 `luainstaller.1`。
系统树 `/usr/local/lib/luarocks/rocks-5.4/luainstaller/1.7.1-1` 同样没有
`LICENSES/`。

源码位置：`luainstaller-1.7.1-1.rockspec` 第 37–76 行的 `build` 表只有
`type`、`modules` 和 `install.bin`，没有 `copy_directories`。
LuaRocks 因此用默认文档复制。本机 LuaRocks 3.13.0 的
`/usr/local/share/lua/5.4/luarocks/build.lua` 里，`install_default_docs`
用 `^license` 命中目录名 `LICENSES`，调用不带 `-r` 的 `cp`，并且不检查返回值。
那是安装器的行为，不是本仓库的函数。
本仓库里独立安装的复制在 `tools/install.lua` 第 100–108 行：第 102–103 行复制三份
`LICENSES` 文件，第 105 行复制 `CHANGELOG.adoc` 和 `luainstaller.1`，
第 107–108 行复制 `docs/*.adoc`。

`src/distribution_files.lua` 的内嵌文本与 `LICENSE`、三份 `LICENSES` 文件、
`THIRD_PARTY_NOTICES.md`、`docs/RELINKING.adoc` 和
`tools/generate-onefile-payload.lua` 逐字节相同。
所以目录形式和单文件产物里的许可证文本没有新的偏差。

`docs/`、变更记录和手册没有进 LuaRocks 安装树，与独立安装的材料集合不一致。
这和 V72-01 是同一次默认复制的结果，不单列为另一个缺陷。
`AGENTS.md` 出现在 `doc/` 里只是因为扩展名是 `.md`。

`max_deps = 1` 且手动包含两个 Lua 文件时，`src/discovery.lua` 第 219 行的
`applyManualInputs` 返回 `DependencyLimitExceededError`，计数为 2。

（第 296 行）。
`src/analyzer.lua` 第 1850 行计数 Lua 依赖，第 1885 行把新的原生库计入同一上限。
这两处只阅读。这是 1.7.1 已关闭的配额行为，当前代码仍这样做。

运行时发现会执行入口。本次没有再跑一个会执行用户代码的运行时扫描，

结果：已检查，无新缺陷。运行时发现执行用户代码、动态 `require` 和

== 继续保留的边界

这些来自 1.7.1 和更早的审计。本次没有看到当前代码仍然做错的新证据，
所以不重新打开：

* 运行时发现执行用户代码。构建工具链和工作区仍需可信。
* 不保证断电后的持久性。目录切换仍有可见间隙。
* 动态 `require` 用 `--include` 或运行时发现。
* `--include` 接受 Lua 源文件，不接受 C 库。本次执行仍拒绝 `.so`。
* 系统库不打进产物。
* Windows 代码页。
* ARM64、macOS、FreeBSD、Termux 和旧 Windows 等补充物理主机。
  本次没有运行它们。
