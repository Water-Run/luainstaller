This guide describes day-to-day packaging: workflow, options, dependency
discovery, and the library API. Install and command mapping are in
xref:../README.adoc[README]. Platform and ABI limits are in
xref:PLATFORMS-NATIVE-LIMITS.adoc[Platforms and native modules].

The tool supports official Lua `>= 5.1` and `< 5.6`. LuaJIT is rejected.
The running interpreter defines the bundle Lua major/minor ABI. Headers,
libraries, discovery, native modules, and the linked runtime must match
that ABI. Lua 5.5 needs LuaRocks `>= 3.13.0`.

The command line has two grammars, `luai` and `luainstaller`. They share
features but not input syntax or terminal output. Do not mix them. The
mapping is in the README. Examples below use `luai`. Logs are available
only through `luainstaller logs`.

[#usage-workflow]
== Workflow

. Run the entry with the same `lua` and module paths that will be packaged.
. Examine dependencies with `luai -a` or `luai -t`.
. Build a directory bundle with `luai -b --dir`.
. Run the bundle with `LUA_PATH` and `LUA_CPATH` cleared.
. Optionally build a single-file executable with `luai -b --file`.

A directory bundle first separates dependency errors from compile and
extract errors.

[source,bash]
----
lua app/main.lua --help
----

Repository fixture, from the repository root:

[source,bash]
----
lua test/runtime_bundle/main.lua direct
----

[#usage-onedir]
== Directory bundle

[source,bash]
----
luai -t test/runtime_bundle/main.lua --max-deps 120
luai -b --dir test/runtime_bundle/main.lua \
  -o build/runtime-demo --max-deps 120

EMPTY_PATH=$(mktemp -d /tmp/luainstaller-empty-path-XXXXXX)
env -i PATH="$EMPTY_PATH" \
  build/runtime-demo/runtime-demo Grace
rmdir "$EMPTY_PATH"
----

Inspect the result:

[source,bash]
----
find build/runtime-demo -type f -print | sort
sed -n '1,220p' build/runtime-demo/.luai/manifest.lua
----

The entry and pure-Lua modules live in the launcher. `.luai/native/`
holds Lua C modules and, on shared-Lua profiles, the runtime library.

Packaged modules win. Undeclared names may still fall through to host
searchers. This is same environment lookup, not a hermetic sandbox.
The clean run above exposes missing packaged dependencies.

[#usage-onefile]
== Single-file

[source,bash]
----
luai -b --file test/runtime_bundle/main.lua \
  -o build/runtime-demo-onefile --max-deps 120
build/runtime-demo-onefile Grace
----

At run time the payload is a content-addressed directory bundle
extracted under the temporary directory. The inner launcher then
starts. POSIX caches are keyed by effective UID. Cache reuse requires
exact byte match. Layout and safety rules:
xref:BUNDLING.adoc[Bundle format].

[#usage-options]
== `luai` options

=== Output

`--dir`::
Directory bundle (default).

`--file`::
Single-file executable.

`-o PATH`::
Output path.

User-owned content is never overwritten. A recognized generated
directory bundle may rebuild through private staging. Only recursive v2
ownership markers are eligible for automatic replace. v1 requires
one-time removal (xref:BUNDLING.adoc[one-time removal]).

=== Dependencies

`--include PATH`::
Add a `.lua` file that discovery missed.

`--exclude VALUE`::
Drop a dependency. The value may be a path, a basename, or a path suffix.

`-d MODE`::
`static`, `runtime`, or `manual` (default `static`).

`--no-depscan`::
Same as `manual`.

`--max-deps N`::
Pure-Lua dependency cap (default 36).

=== Other

`--lua PATH`::
Interpreter for runtime discovery. It must be an official Lua 5.1-5.5
interpreter with the exact major/minor ABI of the active luainstaller
process. When omitted, only verified interpreter candidates from the
launcher argument vector or `lua` on `PATH` are accepted. Otherwise pass
`--lua` explicitly.

`-- ARGS...`::
Arguments for the entry during discovery only.

`--target-os OS`::
Assert the detected host OS. A mismatch fails the command. There is no
cross-build.

`--lua-prefix PATH`::
Headers and runtime prefix. An explicit choice does not fall back to
another installation.

`--verbose`::
Extra trace and counts.

[#usage-discovery]
== Dependency discovery

=== static (default)

Recognizes literal forms such as `require("x")`, `require 'x'`, and
`pcall(require, "x")`. String escapes are decoded.
`local require = require` is followed. Other aliases are not.

Resolution is entry-rooted: templates under the entry directory come
first, then `package.path` and `package.cpath`. Computed names raise
`DynamicRequireError`. Native module names must be literals.

=== runtime

[source,bash]
----
luai -a app/main.lua -d runtime -- profile_a input.json
----

Only loads observed on this run are recorded. Do not use this mode on
entries that mutate data, open the network, or start services at import
time. Native loaders and pre-trace cache limits:
xref:TROUBLESHOOTING.adoc[Troubleshooting].

=== manual

[source,bash]
----
luai -b app/main.lua --no-depscan \
  --include app/core.lua \
  --include app/adapters/sqlite.lua \
  -o build/app
----

`--include` paths must keep structure relative to the entry.

[#usage-native]
== Native modules

Use the same paths as the source program (`5.x` stands for the actual
ABI):

[source,bash]
----
LUA_PATH='/opt/app/share/lua/5.x/?.lua;;' \
LUA_CPATH='/opt/app/lib/lua/5.x/?.so;;' \
luai -b --dir app/main.lua -o build/app --max-deps 250
----

Inspect the copied objects:

[source,bash]
----
find build/app/.luai/native -type f | sort
ldd build/app/app
----

On macOS use `otool -L`. Validate Windows builds on Windows.

[#usage-logs]
== Logs

Only `luainstaller` provides this command:

[source,bash]
----
luainstaller logs
luainstaller logs --level error --limit 20
----

Logs are stored under `~/.luainstaller/`. Compiler output and the
current command's structured errors remain the primary evidence.

[#usage-api]
== Library API

[source,lua]
----
local luainstaller = require("luainstaller")

local analysis = luainstaller.analyze({
    entry = "app/main.lua",
    discovery_mode = "static",
    max_deps = 120,
})
if not analysis.ok then
    io.stderr:write(analysis.error.type, ": ", analysis.error.message, "\n")
    os.exit(1)
end

local built = luainstaller.bundle({
    entry = "app/main.lua",
    mode = "onedir",
    out = "build/app",
    max_deps = 120,
})
assert(built.ok, built.error and built.error.message)
print(built.executable)
----

The structured result contract applies to `analyze`, `trace`, `compatibility`, and `bundle` only.
Success sets `ok = true`. Failure sets `ok = false` with `error.type` and
`error.message`.
`getLogs` returns a list of log records; `clearLogs` returns a boolean.
Unknown option keys for the structured operations raise
`InvalidOptionsError`. Version: `luainstaller.VERSION`.
