当前开发版本为 1.6.1，已发布基线为 1.6.0。本文件记录开发目标与待办。

== 1.6.1：问题解决和梳理

先建立问题清单，记录复现条件、影响、回归测试和处理状态。
按影响处理构建失败、产物行为错误、文件保护和恢复问题，再整理诊断与维护结构。
重构围绕已确认的问题和重复逻辑展开，保持既有 CLI、API 和产物行为兼容。

[%interactive]
* [ ] 核对用户反馈、现有待办与 1.6.0 功能，区分已复现缺陷、待确认问题和改进建议。
* [ ] 重点复核 MoonScript 预处理、目录模式、单文件自动选择、解包与免解包路径。
* [ ] 每个缺陷先增加能复现它的行为测试，再修复实现；核对错误、清理和已有输出保护。
* [ ] 梳理分析、运行时发现、构建与发布边界，减少重复逻辑，保持生成模板与内嵌副本同步。
* [ ] 复核中英文文档、锚点、命令示例和文档契约；验收当前 Unreleased 中的中文文档与视频入口。
* [ ] 完成五个官方 Lua ABI 的回归、两种 CLI 与安装后实际构建验收。

完成条件：问题清单逐项有处理结论，修复都有回归证据，发布提交通过必需门禁。
后续版本所需的运行时扩展和优化接口，以这一版的行为作为回归基线。

== 1.7.0：LuaJIT 支持

将运行时种类与 Lua API/ABI 版本分别记录，让分析、库发现、链接和产物运行
使用同一份运行时身份。LuaJIT 支持覆盖工具运行和生成产物两条路径。

[%interactive]
* [ ] 确定首批支持的 LuaJIT 版本与构建配置，固定测试源码、提交和摘要。
* [ ] 调整 `src/compat.lua`、`src/lua_abi.lua`、`src/toolchain.lua` 和
      `src/launcher.lua` 的识别、能力判断与拒绝逻辑，加入真实运行时探测。
* [ ] 验证 LuaJIT 扩展语法的分析和加载；区分内建模块与发行版附带的 Lua 文件，
      覆盖 `bit`、`jit`、`ffi` 及使用到的 `jit.*` 模块。
* [ ] 验证静态与动态链接、最小 API 声明、C 模块加载和运行库选取，
      诊断解释器、库或目标架构不匹配的问题。
* [ ] 核对 `ffi.load` 外部库的依赖发现与纳入方式，用实际用例确定支持边界。
* [ ] 验证目录、单文件解包和免解包模式的能力选择、失败诊断与重链接材料。
* [ ] 使用清空 Lua 搜索路径、移除原始源码和未安装 LuaJIT 的目标环境验证产物，
      检查 JIT 开启及关闭时的行为。
* [ ] 增加 Linux x86_64 与原生 Windows/MSVC 的 LuaJIT 门禁，保留官方 Lua
      五 ABI 矩阵和原生 Linux x86 门禁。
* [ ] 同步更新 `CODING-STYLE.txt`、双语用户文档、文档契约和原有 LuaJIT 拒绝测试。

完成条件：两条运行路径及发布声明中的构建模式有实际执行证据，
现有官方 Lua 支持通过回归。LuaJIT 的平台覆盖按已验证的组合描述。

实现时参考上游的 link:https://luajit.org/extensions.html[兼容性与扩展说明]、
link:https://luajit.org/install.html[构建说明] 和
link:https://luajit.org/ext_ffi_api.html[FFI API]，并与固定测试版本核对。

== 1.8.0：o1、o2、o3 性能优化器

o1、o2、o3 是 luainstaller 自身的三档优化策略。先测量，再决定各档处理哪些层、
采用哪些优化以及默认值。底层编译器参数可以作为策略的一部分，按编译器能力映射。

=== 先建立基准

[%interactive]
* [ ] 评估并扩展 `tools/benchmark-real-world.sh`，保留可重复的运行方法与原始数据。
* [ ] 分别测量分析、预处理、生成和编译耗时，以及产物冷启动、稳态执行、峰值内存和体积。
* [ ] 覆盖小脚本、多模块项目、MoonScript、C 模块，以及目录和两种单文件启动方式。
* [ ] 分开记录官方 Lua 与 LuaJIT；LuaJIT 记录 JIT 开关、预热条件和冷启动结果。
* [ ] 固定输入、运行时、编译器、构建模式和缓存状态，多次采样并记录波动。

=== 再确定三档策略

[%interactive]
* [ ] 根据瓶颈筛选候选优化，分别评估构建流程、生成代码、模块加载与底层编译设置的收益。
* [ ] 为 o1、o2、o3 明确优化集合、适用场景、构建成本和运行时能力要求，确定默认行为。
* [ ] 确定两种 CLI 和 Lua API 的选项，提供关闭优化的基线，并在结果中记录请求与实际策略。
* [ ] 验证选项无效、能力不足和优化失败时的诊断，以及清理、输出保护和可重现构建。
* [ ] 以关闭优化的程序作差异验证，检查结果、退出码、错误、模块加载和调用副作用；
      对涉及 Lua 代码变换的策略补充调试信息、反射、数值和求值顺序的语义检查。
* [ ] 在两类运行时和实际编译器上比较各档收益、代价与回退，依据测量结果设定性能验收阈值。
* [ ] 将适用场景和使用方式写入双语文档，更新对应契约。

完成条件：三档策略各有明确行为、语义回归和可重复的性能证据；
验收同时报告收益、额外构建成本和出现性能回退的场景。
