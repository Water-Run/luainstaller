按顺序执行以下步骤，在第一个失败的地方停下来。问题就出在那一步。

[source,bash]
----
lua app/main.lua                                   # 1. 脚本能运行吗？
luai -a app/main.lua                               # 2. 模块都能找到吗？
luai -b app/main.lua -o build/app                  # 3. 能构建吗？
env -u LUA_PATH -u LUA_CPATH build/app/app         # 4. 打包结果能独立运行吗？
luai -b --file app/main.lua -o build/app-onefile   # 5. 单文件可用吗？
----

[#troubleshooting-cli]
== "unknown option" 或 "unknown command"

`luai` 和 `luainstaller` 的语法不同：

[cols="1,1",options="header"]
|===
|正确 |错误
|`luai -b main.lua`      |`luai build main.lua`
|`luainstaller build main.lua` |`luainstaller -b main.lua`
|===

要传给脚本的参数放在 `--` 之后：
`luai -a main.lua -d runtime -- --verbose`。

[#troubleshooting-static]
== 缺少某个模块

脚本能用 `lua` 运行，但 `luai -a` 找不到某个模块，或者打包结果以
`module 'x' not found` 失败。

* *环境一致吗？* 让 `luai` 使用与你的脚本相同的 `LUA_PATH` 和
  `LUA_CPATH`，以及相同的 Lua 版本。
* *名称是计算出来的？* 扫描器看不到 `require("plugins." .. name)`。
  用 `--include` 补上这些文件，或者使用 `-d runtime`。
* *`require` 被隐藏了？* 只有 `require` 和 `local require = require`
  会被跟踪，其他别名不会。
* *模块太多？* 调高 `--max-deps`。

`luai -t app/main.lua --verbose` 会显示每个模块的搜索位置。

[#troubleshooting-compile]
== 构建时编译或链接失败

检查编译器和 Lua 库是否适用于当前机器，以及库的版本是否与你正在
运行的 `lua` 一致：

[source,bash]
----
lua -v
cc --version
pkg-config --libs lua
----

如果 `pkg-config` 找到了错误的 Lua 或者什么都没找到，就让
`luainstaller` 指向正确的安装：

[source,bash]
----
luai -b app/main.lua --lua-prefix /opt/lua-5.4
----

前缀目录的 `lib/` 或 `lib64/` 下应当有匹配的 Lua 库，不需要 Lua 头文件。
使用 `--verbose` 可以看到选中的库和查找路径。

.各系统的注意事项
[%collapsible]
====
Linux（32 位）::
解释器、编译器、库和每个 C 模块都必须是 32 位的。只给
编译器加上 `-m32` 是不够的。

macOS::
检查前缀目录下存在 `lib/liblua.a`，并且与你的
Mac 架构匹配。

Windows::
在 Visual Studio 开发者命令提示符（或 MinGW shell）里构建，让
编译器位于 `PATH` 上。前缀目录需要 `lua5x.dll` 和对应的导入库。
MSVC 也可以根据 DLL 的导出符号生成导入库。

Windows XP::
使用支持 XP 的编译器和 C 运行时。新版 Visual Studio 构建出的程序
即使编译通过，在 XP 上也无法启动。从编译器自带的命令提示符运行，
并使用 PowerShell 2 或更高版本。

FreeBSD::
不要加 `-ldl`；它只适用于 Linux。

Android（Termux）::
在 Termux 里安装 `clang` 和 Lua。不要改动 `$PREFIX` 和
`$TMPDIR`，也不要创建 `/tmp` 或 `/bin/sh`。
====

[#troubleshooting-native-dependencies]
== 构建提示 C 模块的库依赖

告警会列出模块及其依赖的外部库。这些库不会复制进打包结果。
请在目标机器上安装它们，或重新构建模块，将这些依赖静态链接。
标记为 `not found on build host` 的库也需要在构建机器上处理。

对于 `libstdc++` 和 `libgcc_s`，请先确认它们与目标机器的 C/C++
运行时兼容，再决定如何分发。

如果告警说明依赖未检查，可在 Linux 上运行 `ldd module.so`，
在 macOS 上运行 `otool -L module.so`。Windows 的 DLL 依赖需要单独检查，
例如在 Visual Studio 开发者命令提示符中运行 `dumpbin /DEPENDENTS module.dll`。

`luainstaller logs --level warning` 可查看保存的诊断记录。
构建可以成功，但目标机器仍可能需要安装这些库。

[#troubleshooting-native]
== 程序启动后某个 C 模块出错

* 检查文件在不在：`ls build/app/.luai/native/`。
* 检查它是否为当前系统构建：`file build/app/.luai/native/*`。
* 检查它自己的依赖库是否齐全：`ldd build/app/.luai/native/*.so`。

如果程序只有在设置了 `LUA_CPATH` 时才能工作，说明它加载的是你机器
上的模块，而不是打包结果里的。

[#troubleshooting-output]
== 重建被拒绝

`luainstaller` 只会替换由它创建、且此后无人改动过的目录。它通过
`.luai/generated-output.txt` 来检查这一点，该文件的第一行必须是
`luainstaller-generated-output-v2`。

如果你手工编辑过这个目录，或者它来自旧版本，请删除它，或者构建到
新的 `-o` 路径。

残留的锁文件形如 `build/.luai-lock-<hash>`。确认没有构建正在运行后，
把它删掉即可。

[#troubleshooting-onefile]
== 单文件无法启动

先确认目录打包可以工作。如果可以，问题出在解包上。检查临时目录
（`$TMPDIR`，Windows 上是 `%TEMP%`）可写且属于你本人。在 Termux 上
不存在 `/tmp`，使用的是 `$TMPDIR`。

清除已解压的副本（先关闭所有正在运行的副本）：

[source,bash]
----
rm -rf "${TMPDIR:-/tmp}/luainstaller-onefile-$(id -u)"
----

[#troubleshooting-errors]
== 错误类型

[cols="2m,3",options="header"]
|===
|类型 |含义

|ScriptNotFoundError         |入口脚本或某个 `--include` 文件不存在
|LuaSyntaxError              |某个源文件无法通过编译
|SourceChangedError          |构建运行期间有文件发生了变化
|DynamicRequireError         |名称为计算得到的 `require`（static 模式）
|ModuleNotFoundError         |在任何搜索路径上都找不到某个模块
|DependencyLimitExceededError |模块数量超过 `--max-deps`
|DuplicateModuleError        |两个文件会落到同一个名称下
|InvalidOptionsError         |选项或值不合法
|InvalidOutputError          |输出目录无法被安全替换
|UnsupportedPlatformError    |`--target-os` 与本机不匹配
|UnsupportedLuaVersionError  |不是官方 Lua 5.1–5.5（LuaJIT 也不支持）
|ToolchainError              |编译器或 Lua 库缺失或不匹配
|CompilationFailedError      |编译器已运行并报告了错误
|LuaRuntimeNotFoundError     |找不到 Lua 共享库
|DiscoveryError              |运行时发现没有完成
|FilesystemError             |文件无法读取、写入或重命名
|===

[#troubleshooting-logs]
== 报告问题

请附上以下内容：

* 完整的命令及其输出，包括编译器的输出
* `luai -v` 和 `lua -v`
* 你的操作系统和 CPU 架构
* 第 4 步（干净环境运行）是否同样失败

`luainstaller logs --level error --limit 20` 会显示最近的错误。发帖
之前请去掉私有路径和敏感信息。
