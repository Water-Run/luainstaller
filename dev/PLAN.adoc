== 1.8.3：质量收敛（当前优先）

沿着输入、依赖发现、代码生成、工具链、产物运行、输出事务、进程清理和安装发布
完整检查一次。对历史待核项和新线索先复现，再以失败回归推动修复；同时检查测试
是否确实覆盖承诺的行为，防止跳过、错误环境或不完整证据被算作通过。

详细范围、执行顺序与验收清单见 xref:PLAN-1.8.3.adoc[1.8.3 实施计划]；
发现、修复和验证证据记在 xref:AUDIT-1.8.3.adoc[1.8.3 审计记录]。
本轮保持现有 CLI/API、运行时和产物模式；必要的兼容性收紧单独说明并验证。

Sol 首轮、Terra 复查与 Astra 最终确认已完成；Sol 正在实施并验证已确认的清单。
首轮已复现入口 `...` 参数丢失和基准驱动的结果判定、时限问题；
Terra 另复现压力规模逗号分隔导致漏测；还有证据保留用法和测试说明维护项，尚未修复。

完成条件：审查范围逐项有结论，已确认的范围内缺陷完成修复与回归，高影响疑点有
证据闭环，最终发布提交通过原生门禁，公开附件与两种无版本号安装验收通过。
1.9.0 的优化实验和功能实现以这些条件全部完成为前置。

== 1.9.0：产物运行效率优化（排队）

原定 1.8.0 的 o1、o2、o3 移至 1.9.0。三档策略针对生成的可执行产物，
改善其执行吞吐、延迟、启动开销和运行内存；具体边界、优化集合与默认值在基准后确定。
编译与打包耗时仅用于记录采用优化的成本，不作为本版优化目标。

以验收后的 1.8.3 建立关闭新优化的产物基线和真实运行负载，再依据热点选择生成代码、
启动、模块加载与链接策略。详细基准、候选方向、语义约束和接口草案见
xref:PLAN-1.9.0.adoc[1.9.0 草案]。

完成条件：每档有明确行为、产物运行收益、语义回归与可重复的数据；同时说明额外的
编译成本、体积变化和性能回退场景。

== 共同交付条件

* 版本、手册、rockspec、安装脚本和双语文档一致。
* 按 xref:../docs/TESTING.adoc[测试指南] 完成本地检查；发布提交通过官方 Lua 和 LuaJIT 原生门禁。
* 验证独立安装、升级、两种 CLI、API 和移除源码后的产物运行。
* 标签与发布附件来自同一提交；发布后下载并核对全部附件。
* 发布步骤以 xref:../docs/TESTING.adoc#testing-luarocks[发布] 为准，中文副本保持一致。
  包括五个 GitHub 附件的 `sha256sum -c SHA256SUMS`、`luarocks upload ROCKSPEC SRC.ROCK`、
  上传报告 `unexpected eof while reading` 时改走文档中的 curl 命令、
  LuaRocks 字节与 GitHub 文件一致，以及空树和旧版升级两次无版本号安装。
  索引里缺的更早 GitHub rock 一并上传。API key 留在本机配置里。
* Release 只写用户可见的变更和必要说明；审计、测试与发布证据另行保存。
* 1.8.3 完成后移除其 PLAN 文件，保留审计记录；更新开发索引与 1.9.0 的基线身份。
