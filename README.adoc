= luainstaller
:toc: macro
:toclevels: 2
:sectanchors:
:sectlinks:

`luainstaller` packages a Lua script into a standalone executable.
The executable does not need a system `lua` command at run time.
The target must belong to the same platform family as the build host.

The tool supports official Lua 5.1 through 5.5. LuaJIT is rejected.
It is released under `LGPL-3.0-or-later` at
https://github.com/Water-Run/luainstaller[GitHub].

The packaging interpreter, the headers, the linked runtime, and every
bundled Lua C module must share the same major.minor Lua ABI.

toc::[]

[#install]
== Install

A complete official Lua environment is required. LuaRocks is optional.

With LuaRocks:

[source,bash]
----
luarocks install luainstaller
----

Confirm the installation:

[source,bash]
----
luai -v
----

NOTE: Lua 5.5 requires LuaRocks 3.13.0 or newer. Older LuaRocks releases
do not recognize the 5.5 install ABI.

Without LuaRocks, run from an extracted source tree:

[source,bash]
----
lua bin/luai.lua -v
lua bin/luainstaller.lua analyze test/runtime_bundle/main.lua
----

Or install offline into a new dedicated directory. The parent of that
directory must already exist:

[source,bash]
----
lua tools/install.lua --prefix "$HOME/luainstaller"
"$HOME/luainstaller/bin/luai" -v
----

Windows uses the same installer and generates `.cmd` launchers.
Source use, shell setup, relocation, and removal are described in
xref:docs/INSTALL.adoc[Installation without LuaRocks].
Building an executable still requires a native C compiler and Lua
headers and library that match the interpreter ABI.

[#usage]
== Usage

`luainstaller` may be used as a command-line tool or as a library.

The command line has two names with separate grammars. The features are
the same; the input syntax and terminal output are not. The two grammars
must not be mixed. `luainstaller` uses subcommands. `luai` uses short
options in the manner of traditional Lua tools.

[cols="1,2,2",options="header"]
|===
|Action |`luai` |`luainstaller`

|Help
|`luai -h`
|`luainstaller help`

|Version
|`luai -v`
|`luainstaller version`

|Analyze
|`luai -a <entry>`
|`luainstaller analyze <entry>`

|Trace
|`luai -t <entry>`
|`luainstaller trace <entry>`

|Build
|`luai -b <entry>`
|`luainstaller build <entry>`

|Logs
|—
|`luainstaller logs`
|===

Unless stated otherwise, the examples below use `luai`. Full option
reference: xref:docs/USAGE.adoc[Usage].

[#usage-cli]
=== Command line

Work in this order:

. Run the source program.
. Analyze or trace the dependencies.
. Build a directory bundle (`--dir`).
. Run the bundle with `LUA_PATH` and `LUA_CPATH` cleared.
. Build a single-file executable (`--file`) only after the directory
  bundle works.

The directory bundle keeps the manifest, generated C, and native
libraries visible. The single-file form is self-extracting. When it
fails, verify the matching directory bundle first.

[source,bash]
----
lua test/runtime_bundle/main.lua direct
luai -a test/runtime_bundle/main.lua --max-deps 120
luai -t test/runtime_bundle/main.lua --max-deps 120
luai -b --dir test/runtime_bundle/main.lua \
  -o build/runtime-demo --max-deps 120
build/runtime-demo/runtime-demo Ada
----

After the directory bundle succeeds:

[source,bash]
----
luai -b --file test/runtime_bundle/main.lua \
  -o build/runtime-demo-onefile --max-deps 120
build/runtime-demo-onefile Ada
----

The output begins with `hello Ada`.

Common `luai` options:

* `--dir` — directory bundle (default)
* `--file` — single-file executable
* `-o` — output path
* `--max-deps` — limit on auto-discovered Lua dependencies
  (default is small; raise it for large applications)
* `-d static|runtime|manual` — discovery mode (default `static`)

Before release, run the artifact at least once without a system `lua`
and with `LUA_PATH` and `LUA_CPATH` cleared. Otherwise the host may
hide a missing dependency.

Platform limits are stated in
xref:docs/PLATFORMS-NATIVE-LIMITS.adoc[Platforms and native modules].
Diagnosis: xref:docs/TROUBLESHOOTING.adoc[Troubleshooting].

Every generated distribution contains the Lua MIT notice, the
luainstaller LGPL/GPL texts, third-party notices, generated C source,
and relinking instructions. Preserve them when redistributing an
artifact, and add the notices and source required by application
dependencies. Details: xref:docs/RELINKING.adoc[Relinking generated
bundles].

[#usage-api]
=== Library use

After installation, `require("luainstaller")` uses the same
implementation as the command line.
The structured result contract applies to `analyze`, `trace`, `compatibility`, and `bundle` only.
Success sets `ok = true`. Failure sets `ok = false` and an `error` table
with `type`, `message`, and related fields.
`getLogs` returns a list of log records; `clearLogs` returns a boolean.
The version string is `require("luainstaller").VERSION`.

[source,lua]
----
local luainstaller = require("luainstaller")

local analysis = luainstaller.analyze({
    entry = "app/main.lua",
    discovery_mode = "static",
    max_deps = 120,
})
if not analysis.ok then
    io.stderr:write(analysis.error.type, ": ", analysis.error.message, "\n")
    os.exit(1)
end

local built = luainstaller.bundle({
    entry = "app/main.lua",
    mode = "onedir",
    out = "build/app",
    max_deps = 120,
})
if not built.ok then
    io.stderr:write(built.error.type, ": ", built.error.message, "\n")
    os.exit(1)
end
print(built.executable)
----

Option names and meanings match the command line. Further API notes:
xref:docs/USAGE.adoc[Usage].

[#platforms]
== Platform coverage

Builds are native. The compiler, Lua headers and library, native
modules, architecture, and target operating system must agree.
Implementation is selected by native capability rather than by a short
operating-system allowlist.

[cols="2,1,2",options="header"]
|===
|System |Architecture |Compatibility path

|Windows XP SP3 / XP x64 SP2 or newer
|x86 / x86_64
|XP API baseline and onefile watchdog fallback; XP-capable CRT and Lua DLL

|Modern Windows
|x86, x86_64, ARM, ARM64
|Native MSVC/MinGW linker-machine selection

|Linux
|x86 and x86_64
|32/64-bit userland detection; shared or static Lua

|Linux
|ARM and ARM64
|Shared or static Lua

|Android / Termux
|native Termux architecture
|App-private prefix, Bionic ABI and Termux temporary root

|FreeBSD
|native architecture
|libc `dlopen`, `sysctl` executable path, shared or static Lua

|macOS
|x86_64 and ARM64
|Static Lua preferred; verified dylib fallback
|===

Windows XP builds require PowerShell 2 or newer and a compiler runtime
that targets XP. Installing a modern compiler on a new host does not by
itself make its CRT XP-compatible. Full requirements:
xref:docs/PLATFORMS-NATIVE-LIMITS.adoc[Platforms and native modules].
Evidence tiers: xref:docs/TESTING.adoc[Testing].
