Work through the steps in order and stop at the first one that fails. That
step is where the problem is.

[source,bash]
----
lua app/main.lua                                   # 1. does the script run?
luai -a app/main.lua                               # 2. are the modules found?
luai -b app/main.lua -o build/app                  # 3. does it build?
env -u LUA_PATH -u LUA_CPATH build/app/app         # 4. does the bundle run alone?
luai -b --file app/main.lua -o build/app-onefile   # 5. does the single file work?
----

[#troubleshooting-cli]
== "unknown option" or "unknown command"

`luai` and `luainstaller` have different syntax:

[cols="1,1",options="header"]
|===
|Right |Wrong
|`luai -b main.lua`      |`luai build main.lua`
|`luainstaller build main.lua` |`luainstaller -b main.lua`
|===

Arguments meant for your script go after `--`:
`luai -a main.lua -d runtime -- --verbose`.

[#troubleshooting-static]
== A module is missing

The script runs with `lua`, but `luai -a` can't find a module, or the
bundle fails with `module 'x' not found`.

* *Same environment?* Run `luai` with the same `LUA_PATH` and `LUA_CPATH`
  as your script, and with the same Lua version.
* *Computed name?* `require("plugins." .. name)` can't be seen by the
  scanner. Add the files with `--include`, or use `-d runtime`.
* *Hidden `require`?* Only `require` and `local require = require` are
  followed. Other aliases aren't.
* *Too many modules?* Raise `--max-deps`.

`luai -t app/main.lua --verbose` shows where each module was searched for.

[#troubleshooting-compile]
== The build fails to compile or link

Almost always, the compiler, the Lua headers and the Lua library don't
match each other or the `lua` you're running. Check them together:

[source,bash]
----
lua -v
cc --version
pkg-config --cflags --libs lua
----

If `pkg-config` finds the wrong Lua or none at all, point `luainstaller` at
the right installation:

[source,bash]
----
luai -b app/main.lua --lua-prefix /opt/lua-5.4
----

The prefix folder should contain `include/lua.h` and a Lua library under
`lib/`.

.Notes per system
[%collapsible]
====
Linux, 32-bit::
The interpreter, compiler, headers, library and every C module must all
be 32-bit. Adding `-m32` to the compiler alone isn't enough.

macOS::
Check that `include/lua.h` and `lib/liblua.a` exist under the prefix and
match your Mac's architecture.

Windows::
Build from a Visual Studio developer prompt (or a MinGW shell) so the
compiler is on `PATH`. The prefix needs the headers, the import library
and the `lua5x.dll`.

Windows XP::
Use a compiler and C runtime that support XP. A modern Visual Studio
build won't start there even though it compiles fine. Run from the
compiler's own prompt, and use PowerShell 2 or later.

FreeBSD::
Don't add `-ldl`; it's Linux-only.

Android (Termux)::
Install `clang` and the Lua development package inside Termux. Leave
`$PREFIX` and `$TMPDIR` alone and don't create `/tmp` or `/bin/sh`.
====

[#troubleshooting-native]
== A C module fails after the program starts

* Check the file is there: `ls build/app/.luai/native/`.
* Check it's built for this system: `file build/app/.luai/native/*`.
* Check its own libraries are present: `ldd build/app/.luai/native/*.so`.

If the program only works when `LUA_CPATH` is set, it's loading modules
from your machine rather than from the bundle.

[#troubleshooting-output]
== The rebuild is refused

`luainstaller` only replaces a folder it created and that nobody changed
since. It checks this with `.luai/generated-output.txt`, whose first line
must be `luainstaller-generated-output-v2`.

If you edited the folder by hand, or it came from an older version,
delete it or build to a new `-o` path.

A leftover lock looks like `build/.luai-lock-<hash>`. Remove it once
you're sure no build is running.

[#troubleshooting-onefile]
== The single file doesn't start

First confirm the directory bundle works. If it does, the problem is
unpacking. Check that the temporary folder (`$TMPDIR`, or `%TEMP%` on
Windows) is writable and belongs to you. On Termux, `/tmp` doesn't
exist; `$TMPDIR` is used instead.

To clear the unpacked copies (after closing all running copies):

[source,bash]
----
rm -rf "${TMPDIR:-/tmp}/luainstaller-onefile-$(id -u)"
----

[#troubleshooting-errors]
== Error types

[cols="2m,3",options="header"]
|===
|Type |Meaning

|ScriptNotFoundError         |The entry script or an `--include` file doesn't exist
|LuaSyntaxError              |A source file doesn't compile
|SourceChangedError          |A file changed while the build was running
|DynamicRequireError         |A `require` with a computed name (static mode)
|ModuleNotFoundError         |A module wasn't found on any search path
|DependencyLimitExceededError |More modules than `--max-deps`
|DuplicateModuleError        |Two files would end up under the same name
|InvalidOptionsError         |A bad option or value
|InvalidOutputError          |The output folder can't be safely replaced
|UnsupportedPlatformError    |`--target-os` doesn't match this machine
|UnsupportedLuaVersionError  |Not official Lua 5.1–5.5 (LuaJIT included)
|ToolchainError              |Compiler, headers or library missing or mismatched
|CompilationFailedError      |The compiler ran and reported errors
|LuaRuntimeNotFoundError     |The Lua shared library couldn't be located
|DiscoveryError              |Runtime discovery didn't finish
|FilesystemError             |A file couldn't be read, written or renamed
|===

[#troubleshooting-logs]
== Reporting a problem

Please include:

* the full command and what it printed, including compiler output
* `luai -v` and `lua -v`
* your operating system and CPU architecture
* whether step 4 (the clean run) also fails

`luainstaller logs --level error --limit 20` shows recent errors. Remove
private paths and secrets before posting.
